THE BIG ONE / STILL GOING

A creature with
simulated muscles

I wanted to know whether a creature could learn to stand using muscles instead of animation curves. So I wrote the physics solver. Then the muscle authoring tools. Then made it run 2048 times at once, because reinforcement learning is hungry.

It still can't stand. The falling over, however, is now way more physically accurate.

UNITY TOOLING

Pathfinding for things
that walk on ceilings

NavMesh assumes you have a floor. Ceiling-crawlers disagree. So I voxelised the whole volume instead, then packed 64 walkability bits into a single ulong so the grid wouldn't eat all the RAM.

// WHOAMI

I'd rather spend a week on the tool
than a day on the animation.

I'm Corentin. Technical animator — which mostly means I'm the person you ask "can the character do this?", and I disappear for a while and come back with a tool.

I like the part of animation that turns into maths. Joint conventions, solver stability, why the units are wrong, whether a NaN is sneaking past the fall detection. I will happily read a robotics paper from the eighties to make a monster shift its weight convincingly, and I think that is a completely reasonable trade.

The other half of the job is making sure nobody else has to care about any of that. A solver nobody can configure is just an expensive crash.
